# Elevator Controller — PIC16F1827

Final project for the **Embedded Electronics** course. Firmware that controls a 4-floor elevator model (floors 0–3) using a **PIC16F1827** microcontroller running at 5 V.

Built with **MPLAB X IDE**, the **XC8** compiler (v2.45) and **MPLAB Code Configurator (MCC)**; versioned with GitHub Desktop and VS Code.

📺 Demo video: https://youtu.be/kguAqlnOZeQ

---

## Overview

Users request a ride by sending a command over the serial port (pickup floor and destination floor). The elevator travels to the requested floor, showing the current floor along the way. When it reaches a stop, it pauses for **2 seconds** for boarding/unboarding and checks for new calls. If a new request arrives, it goes to that floor; otherwise, it returns to the ground floor (floor 0).

An **8×8 LED matrix** (MAX7219 driver) acts as the control panel, showing:

- the **current floor** (digit 0–3), and
- the **direction of travel** (up arrow, down arrow, or a straight line when stopped).

## How it works

| Function | Peripheral |
|---|---|
| Serial command input | EUSART — 19200 baud, 8N1 |
| Motor speed | PWM3 (≈40 % duty cycle while moving) |
| Motor direction | Digital output `DIR` (RA7) |
| Floor 0 / floor 1 sensors | Interrupt-on-change on RB0 / RB3 |
| Floor 2 / floor 3 sensors | Comparators CMP1 / CMP2 |
| Encoder / position pulses | CCP4 capture |
| LED matrix (MAX7219) | MSSP1 in SPI mode, chip select on RB1 |
| Clock | Internal oscillator, 16 MHz |

### Control logic

1. **Request queue.** Each request is stored as an `{origin, destination}` pair in a queue of up to 5 entries. Per-floor flags (`flagOrigens`, `flagDestinos`) track which floors have pending pickups and drop-offs.
2. **Floor events.** Every floor sensor triggers an interrupt handler (`Andar0` … `Andar3`). The handler updates the current floor, serves any pickups or drop-offs on that floor (stop the motor, wait 2 s, mark requests as processed), and decides the next direction.
3. **Direction decision.** At the intermediate floors (1 and 2), the firmware keeps the current direction while there are pending requests ahead and reverses otherwise. Floor 0 always goes up and floor 3 always goes down when there is work left. With an empty queue the elevator stays parked at floor 0.
4. **Display.** After each event the LED matrix is redrawn over SPI with the floor digit and the direction symbol.

### Serial protocol

Each request is a frame of 4 bytes:

```
$ <origin> <destination> <CR>
```

- `$` — start of frame
- `<origin>` — pickup floor, ASCII `'0'`–`'3'`
- `<destination>` — destination floor, ASCII `'0'`–`'3'`
- `<CR>` — end of frame (`0x0D`)

Example: `$12` followed by `0x0D` requests a ride from floor 1 to floor 2. Requests where origin equals destination are ignored.

## Running it locally

### Requirements

- [MPLAB X IDE](https://www.microchip.com/mplab/mplab-x-ide) (v6.x recommended)
- [MPLAB XC8 compiler](https://www.microchip.com/xc8) — the project targets **v2.45**
- Device pack **PIC12-16F1xxx_DFP** (MPLAB X installs it on demand)
- Optional: MCC plugin, only if you want to change the peripheral setup (`PF_GRUPO3.mc3`)
- To run on hardware: a PIC16F1827 board, a programmer (PICkit 3/4/5 or MPLAB Snap), a MAX7219 8×8 LED matrix, a DC motor with driver, floor sensors, and a USB-to-serial adapter

### Build

1. Clone the repository:
   ```bash
   git clone https://github.com/jpbandeiraraposo/Embedded_Electronics.git
   ```
2. In MPLAB X, choose **File → Open Project** and select `Elevator-Controller-PIC16F1827/PF_GRUPO3.X/PF_GRUPO3.X`.
3. Under **Project Properties**, check that the device is **PIC16F1827** and the compiler is **XC8**. If v2.45 is not installed, pick the version you have.
4. Click **Clean and Build** (hammer and broom icon). The `.hex` file is written to `dist/default/production/`.

### Run in the simulator (no hardware)

1. In **Project Properties → Hardware Tool**, select **Simulator** (the default for this project).
2. Start a debug session (**Debug → Debug Main Project**).
3. Open **Window → Simulator → Stimulus**, add a UART1 RX stimulus, and send a frame such as `"$12"` followed by `0D`. `Projeto_Final_EQUIPE3.X/usart_estimulos.txt` has a ready-made example.
4. Floor sensors can be simulated by toggling RB0 / RB3 (floors 0 and 1) and the comparator inputs (floors 2 and 3) in the stimulus window.

### Run on hardware

1. Wire the peripherals as listed in the table above. The exact pin assignments are in `mcc_generated_files/pin_manager.c`.
2. Under **Project Properties → Hardware Tool**, select your programmer and click **Make and Program Device**.
3. Open a serial terminal (PuTTY, Tera Term, the Arduino Serial Monitor, etc.) at **19200 baud, 8N1**, then send `$` + origin + destination + carriage return, e.g. `$03⏎`.
